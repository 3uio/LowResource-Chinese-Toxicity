## 2. 🔴 四条硬约束（不可协商）

### 2.1 表5 只读

- 表5 只放只读目录，**严禁**把表5 路径写进任何生成脚本的输入参数；
- 表2 / 表3 / 表1 写入前**必须**过泄漏查重，命中即**报错**（不是警告）；
- 表5 全文**不得提交进仓库**，只提交**文本哈希**。

### 2.2 同一 `source_id` 不跨 split

同一句原文（同一 `source_id`）的所有变体必须**整体落在同一个 split**。原因：否则同一句话的变体出现在 train 和 test 两边，直接构成泄漏。

- split **只在种子层分配一次**，变体一律继承；
- 校验脚本会拦（跨 split 即报错）。

### 2.3 泄漏查重必须做归一化，不能只做精确匹配

**实测依据**：5 个分隔符类变体（`傻*子` / `傻.子` / `傻 子` / `傻—子` / 零宽字符）**全部绕过精确匹配**，只有归一化匹配能抓到。

> **结论：归一化是防泄漏的唯一有效手段。**

**统一归一化流程（顺序固定，全队共用同一份实现）：**

```
NFKC（统一全/半角、统一兼容字符）
  → 去零宽字符（U+200B/200C/200D/FEFF）与 BOM
  → 去全部空白与标点
  → 转小写
  → 繁转简
  → SHA-256
```

⚠️ **顺序不同 → 哈希不同 → 两边查重结果对不上，等于没查。**

⚠️ **第 5 步「繁转简」不是可有可无的。** 实测证据（用 2,041 条种子比对）：

| 实现 | 一致率 |
|---|---|
| 4 步（**缺**繁转简） | 2,025 / 2,041 |
| 5 步（含 `zhconv`） | 2,041 / 2,041 |

那 16 条不一致的全部含繁体字（如 `來`/`們`/`國`/`後`/`無`/`爭`）。缺这一步会让**含繁体字的文本在跨表查重中漏报**。

> 依赖：`python -m pip install zhconv`。

**两套口径要分开用：**

| 场景 | 口径 |
|---|---|
| 表1 内部去重 | **精确匹配**（一字不差） |
| 跨表查重（表1 ↔ 表2/表3/表5） | **必须归一化** |

### 2.4 按来源删数据时，必须连带处理"跨来源孪生副本"

**这是一处会静默失效的坑**（Track A 实测发现）：

数据集之间的去重顺序固定（如 `COLD → ToxiCN → CNTP`）、**先到者胜**。因此同一段文本在多个来源里都有时，只保留最先命中的那一条。

后果：**如果只删掉"预留来源"里的那一行，它在其他来源里的孪生副本会变成唯一，从而漏回数据集。**

实测：
```
❌ 只删 ToxiCN 预留行      → 仍残留 2,041 条（全部经 CNTP 漏回）
✅ 同时排除 CNTP 孪生副本  → 残留 0 条
```

**规则**：任何"按来源排除/预留"的操作，都必须**按归一化哈希跨全部来源一起排除**，不能只按单来源删。

同样地，`CNTP base` 这类"从别处抽样再扰动"得来的数据**自身不带 split 标签**，所以"排除 test/dev"这个动作对它**匹配不到**，必须靠**文本比对**（实测有 1,054 条 CNTP 行其实是 ToxiCN test 的内容）。

## 3. 字段规范

### 3.1 种子表（表2 种子）

| 字段 | 必填 | 说明 |
|---|---|---|
| `source_id` | ✅ | 全局唯一，规则见 §4.1 |
| `text` | ✅ | 原始中文文本 |
| `target_span_start` / `target_span_end` | ✅ | **目标敏感词的字符偏移**（0 基，含 / 不含） |
| `target_span_text` | ✅ | `text[start:end]`，供人工核对 |
| `toxicity_label` | ✅ | 1=有毒，0=非毒 |
| `source_dataset` | ✅ | `ToxiRewriteCN` / `ToxiCN` / `other` |
| `orig_file` / `orig_line` | ✅ | 溯源用 |
| `split` | ✅ | `train` / `dev` / `test` |
| `dup_of` | ⬜ | 若与另一条种子原文重复，填对方 `source_id` |

> 💡 `target_span` 系列是**规则型变体生成的前置条件**：没有它，生成器不知道该替换哪几个字，`PY_Full` 会把整句变拼音、`Homo` 会随机替换任意字，产出的不是"伪装的目标词"而是垃圾。**建议同步补进 V2 第 4 节的字段列表。**

### 3.2 变体表（表2 变体）

| 字段 | 必填 | 说明 |
|---|---|---|
| `source_id` | ✅ | 外键 → 种子表 |
| `variant_id` | ✅ | 全局唯一，规则见 §4.2 |
| `text` | ✅ | 变体文本 |
| `attack_family` | ✅ | `phonetic` / `graphic` / `symbolic` |
| `attack_type` | ✅ | 8 小类之一，见 §5 |
| `secondary_attack_types` | ⬜ | 分号分隔，可为空 |
| `is_adversarial` | ✅ | 表2 变体一律为 1 |
| `generation_method` | ✅ | `rule`（C）/ `llm`（D）/ `manual` |
| `generation_rule_id` | ✅ | 规则 ID，或 prompt 模板 ID + 模型版本 |
| `recoverability` | ⬜ | `recoverable` / `unrecoverable`（**建议新增**，用于 MR 判定） |
| `semantic_score_raw` / `_normalized` | ⬜ | 口径见 §6 |
| `quality_pass` | ✅ | `pass` / `fail` / `pending` |
| `qc_reviewer_1` / `qc_reviewer_2` / `qc_arbiter` | ⬜ | 质检留痕（**必须是未生成该批数据的人**） |
| `split` | ✅ | **必须等于该 `source_id` 在种子表中的 split** |
| `substitution_unit` | ⬜ | **`char`（字级）/ `word`（整词级）**，见 §3.3 |

### 3.3 `substitution_unit`：替换单位的记录（2026-02-05 新增）

**为什么需要它**：实测发现**逐字替换对多字目标词不成立**。
98% 的种子目标词是多字的，逐字替换会产出伪样本：

```
母狗 逐字换 → 目狗 / 幕勾 / 姆苟   ← 不成话
母狗 整词换 → 幕狗 / 穆狗          ← 成立
```

所以规则改为**整词优先、字级兜底**，并记录每条变体用的是哪种：

| 取值 | 含义 |
|---|---|
| `word` | 整词替换（键为目标词，如 `母狗` → `幕狗`） |
| `char` | 字级替换（逐字查表，仅用于单字目标或整词表未命中时） |

**用途**：

1. **消融分析**："字级 vs 词级"哪种更难被模型识破；
2. **可恢复性差异**：`母狗→目狗` 基本不可恢复（读者拼不回），
   `母狗→幕狗` 可恢复 —— 直接对应 `recoverability` 字段与 V2 第 5 节的 `MR` 判定。

⚠️ **待确认**：该字段目前是**提案**（与 `target_span` 一样需补进 V2 第 4 节）。

## 4. ID 命名规则（必须冻结，否则不可追溯）

### 4.1 `source_id`

格式：`<dataset_code>-<归一化哈希前 10 位>[ -<序号> 仅当哈希整串重复时 ]`

| code | 数据集 |
|---|---|
| `trcn` | ToxiRewriteCN |
| `toxi` | ToxiCN |
| `cold` | COLD |
| `cntp` | CNTP |

**示例**：`toxi-c478e0f3eb`、`toxi-c478e0f3eb-2`

> **为什么不用行号**：实测 `ToxiCN` 的 `train.json` 是**整个文件一行的紧凑 JSON 数组，不存在物理行号**，`<dataset_code>-<orig_line>` 这条规则落不了地。

> **为什么加长哈希前缀解决不了冲突**：存在"原文不同、归一化后相同"的行（如 `女拳***` 与 `女拳？？？`），它们的**哈希整串完全相同**，8/10/12/16 位前缀都有同样 2 组冲突。因此**哈希重复时必须靠序号区分**。

**实测**：2,041 条候选 -> 生成 2,041 个 `source_id`，**全部唯一**（仅 2 个需要序号后缀）。

三条硬要求：

1. **全局唯一**——冲突时加序号，**不要靠加长前缀**（见上）；
2. **稳定**——由原文内容派生，与清洗顺序、文件格式、行号基准全部无关；
3. **可溯源**——`source_id` 可反查回 `source_dataset` + `orig_file` + 行号；**种子表须同时保留行号列**（行号只作辅助溯源，不作主键）。

### 4.2 `variant_id`

格式：`<前缀>-<source_id>-<attack_type>-<两位序号>`

| 类型 | 示例 |
|---|---|
| 规则型（C） | `r-toxi-c478e0f3eb-Homo-01` |
| LLM 型（D） | `l-toxi-c478e0f3eb-Homo-01` |

- 前缀：`r-` = 规则型，`l-` = LLM 型 —— **命名空间分离，便于"规则 vs LLM"消融与溯源**；
- 序号在同一 `(source_id, attack_type)` 内从 `01` 递增。

## 5. `attack_type` 八小类

| # | family | attack_type | 中文名 |
|---|---|---|---|
| 1 | phonetic | `PY_Full` | 全拼替换 |
| 2 | phonetic | `PY_Abbr` | 拼音首字母缩写 |
| 3 | phonetic | `Homo` | 同音／近音字替换 |
| 4 | graphic | `Graph_Similar` | 形近字替换 |
| 5 | graphic | `Graph_Split` | 部件拆分／重组 |
| 6 | symbolic | `Sym_Leet` | 数字／拉丁字母混写 |
| 7 | symbolic | `Emoji_Sub` | 表情符号替换 |
| 8 | symbolic | `Sym_Separator` | 分隔符／干扰字符插入 |

**完整判据、正反例、优先级规则见 `数据构建/docs/01_attack_type定义_v1.0.md`（待冻结）。**

### 5.1 🔴 与 D 的接口约定

| 项 | 规则型（C） | LLM 型（D） |
|---|---|---|
| `generation_method` | `rule` | `llm` |
| `variant_id` 前缀 | `r-` | `l-` |
| `generation_rule_id` | 规则 ID（如 `HOMO-001`） | prompt 模板 ID + 模型名版本 |
| 分类依据 | **同一份 `attack_type` 定义** | **同一份 `attack_type` 定义** |
| 质量卡口 | **同一个 `quality_pass` 判据** | **同一个 `quality_pass` 判据** |

**两条硬要求：**

1. D 的 prompt **必须要求模型输出上述 8 类类名**；
2. 若模型输出的类名**无法映射到这 8 类**，该样本记为 **`attack_type=UNMAPPED` 并单独统计**，**不得硬塞进最接近的一类**。

### 5.2 一条变体只记一个 primary

真实网络文本常是复合攻击（如 `沙*比` 同时命中 `Homo` 和 `Sym_Separator`）。**必须先定死规则，否则多人标注口径一定分叉。**

- 每条变体记录**恰好一个 primary `attack_type`**，可另记 `secondary_attack_types`；
- primary 按"伪装机制的最内层"判定，优先级：
  `Homo > PY_Full > PY_Abbr > Graph_Similar > Graph_Split > Emoji_Sub > Sym_Leet > Sym_Separator`；
- `Sym_Separator` 是**兜底类**：只有没有任何替换机制时才判给它。

## 6. `semantic_score` 口径（🔴 待 D 确认）

| 项 | 提案 |
|---|---|
| 计算对象 | 种子原文 vs 变体文本（**句级**） |
| 工具 | 中文句向量模型（BGE / text2vec 系）余弦相似度 —— **需 D 指定具体模型 + 版本号** |
| `semantic_score_raw` | 原始余弦值，范围 `[-1, 1]` |
| `semantic_score_normalized` | `(raw + 1) / 2` → `[0, 1]` |
| 版本记录 | **必须**记录模型名 + 版本号，否则跨批次不可比 |

⚠️ **不要预设阈值。** 语义相似度对**谐音类**会偏高、对**形近字类**会偏低，**阈值必须按 8 小类分别用实测分布倒推**——与 V2 对 DAPT 止损线的处理原则一致（不套用外部文献数字）。

## 7. `quality_pass` 判据（阈值待实测倒推）

一条变体判 `pass` 需**同时**满足：

1. **可读性**：受过中等教育的母语者能读回原词／原攻击意图；
2. **自然性**：像真实网络用语，不是机器硬凑的生僻字串；
3. **语义保持**：`semantic_score_normalized` ≥ 阈值（**阈值不预设**，pilot 后倒推）；
4. **无泄漏**：未从表5 派生；
5. **无重复**：与已有变体不重复。

**质检流程**：双人独立审 + 不一致时仲裁。V2 第 6 节硬要求：**审的人必须是未生成该批数据的另外两人**，四人轮换。

## 8. 表3（安全对照集）接口

| 字段 | 说明 |
|---|---|
| `item_id` | 唯一 ID，`sc-<三位序号>` |
| `text` | 文本 |
| `sensitive_category` | 5 类之一，见下 |
| `intended_label` | 表3 全部应为 `safe` |
| `team_label` / `ext_label_1` / `ext_label_2` | 团队 / 外部标注者结果 |
| `agreement` | `agree` / `disagree` / `arbitrated` |
| `arbiter` | 仲裁人 |
| `guideline_version` | **必填**。混用两个版本的批次不可用于最终 ER 报告 |
| `split` | 一律 `test` |

**5 类"敏感但非毒性"**：`ref_quote`（学术/新闻引用）、`advocacy`（反歧视倡导/科普）、`in_group`（自嘲/群体内部称呼）、`neutral_discuss`（涉及敏感群体的中性讨论）、`homonym_irrelevant`（含敏感词成分但语义无关）。

⚠️ **表3 是自建数据，但仍需与表5 查重** —— 若某条正常文本恰好出现在表5 test 里，会造成评估污染。

## 9. 统计口径的接口（🔴 待 D 确认）

V2 第 5 节要求 `source_id` grouped bootstrap + McNemar + Holm correction。

**C 的主张**：**分组单位必须是 `source_id`**，不是变体。否则同一句原文的 5 个变体会被当成 5 个独立样本，**低估方差、虚高显著性**。分组单位与 split 单位一致才自洽（V2 第 4 节：同一 `source_id` 不跨 split）。
